# 第15章：模型量化、蒸馏与高效部署 / Chapter 15: Quantization, Distillation, and Efficient Deployment

## 概览 / Summary
· 本章围绕“把大模型更快、更省地跑起来”展开，主线是量化、蒸馏与部署优化三件事如何协同落地。  
· 量化解决“同样模型更省显存/更快推理”，蒸馏解决“把模型从根本做小”，部署优化把理论收益转成真实延迟与吞吐提升。  

## 学习目标 / Learning Outcomes
· 能根据精度与成本约束，选择 PTQ/QAT、量化对象与混合精度策略，并理解常见掉点原因与补救方法。  
· 能理解蒸馏的基本目标与训练要素，并知道从导出到推理引擎的关键优化点（图优化、融合、批处理、KV 缓存）。  

## 关键内容 / Key Topics
· 量化定义：FP16/BF16/FP32 → INT8/INT4，降低权重与中间数据体积，减少带宽压力并可能加速矩阵乘。  
· PTQ vs QAT：部署前快速试水与校准，对比训练中引入量化噪声以稳定低比特精度。  
· 量化对象：权重量化优先，其次是激活量化与 KV 缓存量化（面向长上下文显存瓶颈）。  
· 敏感层与异常值：低比特掉精度往往集中在少数层，典型手段是混合精度、按通道/按组缩放与保护关键层。  
· 蒸馏目标分类：logits 蒸馏、特征蒸馏、任务蒸馏（教师生成数据/偏好/轨迹用于训练学生）。  
· 蒸馏训练要素：温度 T 软化分布、蒸馏损失与监督损失并存、权重平衡决定“像教师”与“对齐答案”的取舍。  
· 量化 vs 蒸馏取舍：量化落地快成本低，蒸馏更彻底但需要数据与训练流程，工程上常组合使用。  
· 部署链路：PyTorch 训练完成后导出 ONNX/TorchScript/引擎格式，再由推理引擎在 GPU/CPU/NPU 执行。  
· 图优化与算子融合：减少中间张量落地与 kernel 启动次数，核心是“少搬数据、少启动 kernel”。  
· 并行与批处理：batch 提升吞吐但可能增加单请求延迟，异步流水线重叠数据准备与计算，多卡并行引入通信与同步开销。  
· KV 缓存工程管理：KV 随生成步数与上下文长度增长，占用显存并限制并发；常见优化是分页/分块、KV 量化与上下文截断/摘要策略。  
· 端侧部署差异：GPU 吞吐强但功耗与成本高；CPU 通用但更依赖 INT8 与高效内核；NPU 省电高效但算子与量化格式约束更强。  

## 运行提示 / Notes
· 建议先跑通“单机单卡端到端链路”，再用 profiling 找瓶颈后逐步引入量化、融合、批处理与并行。  
· 低比特优先从权重量化开始，遇到掉点再考虑混合精度与 QAT，长上下文场景再评估 KV 量化。
